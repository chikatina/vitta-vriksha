# Vitta Vriksha (वित्तवृक्ष)

A personal finance tracker for Indian households that keeps everything on the device it
runs on. Free, open source, and built without a server to talk to.

The app declares no `INTERNET` permission. Every calculation, every PDF parse and every
byte of storage happens on the phone, and there is no code path that could send your
records anywhere. Data leaves only through an export you trigger and encrypt yourself.

## What it does

**Money in and out**
Log what you spent or received, split a bill with the people who owe you, and attach
cashback so the ledger shows what a purchase actually cost you rather than the sticker
price. Investments are recorded separately from spending, so a SIP debit does not make a
frugal month look extravagant.

**Where you stand**
Net worth across cash, bank, deposits, equities, mutual funds and retirement accounts,
minus what you owe on loans and cards.

**A home screen you assemble**
Pick the panels you want and the order they sit in. Alongside the plain totals there are
charts drawn from the history already in the database: income against spending month by
month, spending stacked by category or by person, a running total of what you have kept,
what you have put into investments, and where the money actually goes by shop. A panel with
nothing to show stays hidden until it has data.

**Budgets**
An overall monthly cap plus a per-category cap where you want one, tracked against the
current month as you go.

**Commitments**
SIPs, EMIs, credit card statements and subscriptions, merged into one list of what is due
in the next thirty days.

**Planning**
A retirement target with lean, fat and coast variants, and a prepayment calculator that
shows what an extra monthly payment does to a loan's interest and tenure.

**Bank SMS**
Optional. Grant it and incoming bank alerts are matched against rules you can read, edit
and test on a pasted message. Off by default, and the app is fully usable without it.

**Account statements**
Import a consolidated account statement from any of the four issuers. CAMS and KFintech
cover your mutual funds, with the full transaction history. NSDL and CDSL cover the same
funds plus your demat account: shares, exchange-traded funds, bonds and any National
Pension System holdings. The PDF is parsed on the device and never uploaded, and your PAN
and name are not stored.

**Capital gains**
From a detailed registrar statement, what you actually realised: units matched first in
first out, grandfathering applied to anything held from before 1 February 2018,
purchase-side stamp duty counted into the cost and the transaction tax correctly left out.
It writes the Schedule 112A file the filing utility takes, and the split of the year into
the five advance-tax windows. Check it against your registrar's own statement before you
file.

**Households**
Optional profiles for the people whose money you track, with every screen filterable to
one person or shown for everyone together.

**Backup**
A single encrypted file, AES-GCM with a key stretched from your password through PBKDF2.
Lose the password and nobody can open it, including us.

## Architecture

Two layers in one process:

```
assets/www          HTML, CSS and ES modules. UI and all logic.
      |             SQLite WASM, pdf.js, WebCrypto, in process
      |             window.AndroidBridge
Kotlin              Thin shell: file bytes, biometrics, permissions, alarms, SMS.
```

The Kotlin layer does only what a web page cannot: durable storage, the fingerprint
prompt, the permission dialogs, an alarm that outlives the process, and the share sheet.
Six methods and two receivers. Everything that decides something is JavaScript.

It used to be three layers, with the middle one an embedded Python runtime. That runtime
was 59 MB of a 75 MB build and existed almost entirely for the one job it could not do,
which was reading a depository statement. See
[docs/MIGRATION-JS-BACKEND.md](docs/MIGRATION-JS-BACKEND.md) for what it cost, what was
measured, and how the change was made without touching the database file.

The web layer has no build step. There are four bundled dependencies, each generated by a
script under `tools/` and each with a reason it is not written here: SQLite compiled to
WebAssembly, Mozilla's pdf.js, our own statement parser, and the reference database of
mutual fund schemes. Icons come from a subsetted Material Symbols font, since a CDN is not
reachable and should not be.

| Path | Contents |
| --- | --- |
| `app/src/main/assets/www/js/views/` | One module per screen |
| `app/src/main/assets/www/js/backend/` | Schema, migrations, CRUD, crypto, statement import |
| `app/src/main/assets/www/js/ui.js` | Toasts, dialogs, sheets, menus |
| `app/src/main/assets/www/css/style.css` | Design tokens and every component |
| `app/src/main/assets/www/vendor/` | The four bundled dependencies, generated |
| `tests/` | Node unit and backend test suites |
| `.maestro/` | Automated UI and store screenshot Maestro test flows |
| `tools/` | Automation tools: version bumper, release builder, tablet screenshot orchestrator, font/icon subsetters |
| `release/` | Production-ready signed `.aab` and `.apk` bundles |

## Building & Development

You need a JDK 17 or newer and the Android SDK. No Python, no NDK, and no native toolchains are required during build.

- **Node 20+**: Runs the 58+ unit tests and smoke tests.
- **PowerShell / Bash**: Runs the build, versioning, and test runners.

### Quick Start Commands

```powershell
# Run backend and integration unit tests
node --test tests/run-all.mjs

# Bump version code and name (e.g., patch / minor / major)
.\tools\bump-version.ps1 -Type patch

# Build signed release App Bundle (.aab) and APK (.apk)
.\tools\build-release.ps1

# Or bump & build in a single step
.\tools\bump-version.ps1 -Type minor -Build
```

### Automation & Dev Scripts (`scripts/dev`)

`scripts/dev` (or `scripts\dev.cmd` on Windows) finds the toolchain, builds, installs over adb, launches the app, and tails logs:

```bash
./scripts/dev doctor      # Check the toolchain and list attached devices
./scripts/dev run         # Build, install, launch, and follow logs
./scripts/dev install     # Build and install debug APK
./scripts/dev logs        # Stream this app's logs only
./scripts/dev test        # Run the backend test suite
./scripts/dev web         # Serve the app in a desktop browser (with full local backend)
```

### Automated UI & Store Screenshot Testing (Maestro)

Store screenshots and end-to-end user flows are automated using [Maestro](https://maestro.mobile.dev/):

```powershell
# Run full tablet (7" & 10") screenshot capture pipeline
.\tools\capture-tablet-screenshots.ps1

# Run phone store showcase flow
.\tools\run-pixel8-and-maestro.ps1 -Flow .maestro/07_store_screenshots.yaml
```

### Releases

```powershell
.\tools\bump-version.ps1 -Type patch -Build
```

The output signed artifacts are automatically placed into the `release/` folder:
- **`release/vittavriksha-v<version>-release.aab`**: Signed App Bundle for Google Play Console.
- **`release/vittavriksha-v<version>-release.apk`**: Universal standalone release APK.

The signing key is configured via `keystore.properties` pointing to `release.jks`.

### Working on the Web UI

The web layer needs no compilation step. `./scripts/dev web` serves `app/src/main/assets/www` with the complete database engine and statement parser running directly in the browser via `localStorage`.
